# Automatic provider model discovery validation

Author: Alex Hu / Codex. Date: 2026-10-02. Source: the commit containing this record (parent 74a77db). Upstream: Alex's report that his key grants access to more GPT models than the preset list. Downstream: provider catalog persistence, sidebar/modal lifecycle, privacy documentation and installed assets.

A real, user-authorized discovery through the existing configured provider returned 127 model entries. The existing stored key stayed inside the plugin/Obsidian credential path; it was not read out, replaced, logged or committed by the agent. No inference request or private note write was performed. The provider's list response alone does not guarantee tool-calling capability for every entry. Official API reference: https://developers.openai.com/api/reference/resources/models/methods/list (accessed 2026-10-02).

Fix: assistant open and provider changes refresh the active provider catalog through authenticated GET /models; editing a saved provider and leaving a newly entered key field also discover models. Sidebar refresh is available. Model state persists up to 1,000 IDs instead of silently dropping choices after 100. Failed discovery leaves cached models and the active selection unchanged. HTTP 403 discovery failure is distinct from a rejected key, supporting endpoints whose list permission differs from inference permission. Preset/custom fallback and first-page discovery limits remain documented.

Checks passed: typecheck; 244 tests across 15 files; real CJS bundle smoke; release checks; packaging. Regressions retain all 127 discovered IDs and select a model after the previous 100-choice boundary; a 403 preserves the cached list and active model. Limits above 1,000 are rejected. Actual host smoke verifies automatic GET and state persistence, including command opening through the shared operations queue; discovery starts without being awaited by onOpen, preventing a queue deadlock. hosted inference remains untested.

Deployment: three rebuilt assets were installed and hash-verified in the existing undo vault and the synthetic demo vault, with previous assets backed up. Native settings showed Auto Scheduler enabled during the reload sequence. Inspection then found that awaiting queued discovery inside queued sidebar opening could deadlock; onOpen now starts discovery without awaiting it, with a dedicated host regression. The corrected assets were recopied and verified. Before this update, native discovery visibly reported Connected; found 127 models. Subsequent accessibility control timed out after closing settings, including fresh connections; final verification that the updated sidebar displays the complete catalog remains pending. This does not imply the sidebar has been visually verified. The user was asked to reopen the undo window for that final check.

Review: no automatic inference or credential rotation; discovery remains bound to the configured endpoint and requires a stored/newly entered key when appropriate. Automatic discovery behavior is disclosed in README/privacy/usage. Model lists may contain non-chat models; availability and tool support are separate. No release or community submission was performed.
