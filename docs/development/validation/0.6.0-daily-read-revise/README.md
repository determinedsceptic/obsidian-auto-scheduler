# Daily plan read and revision validation

Author: Alex Hu / Codex. Date: 2026-10-02. Source: the commit containing this record, parent ca6000d. Upstream: the assistant said it could not read or move existing plans. Downstream: bounded provider tools, daily/task transactions, recovery and installed plugin assets.

The assistant now exposes read_daily_plan and revise_daily_tasks. Four provider protocols preserve native tool-call IDs/content, including Gemini thought signatures, through up to three sequential reads. Only requested Day planner checkbox summaries go to the provider. Other note sections, tracking, whole task state and credentials stay local. The host selects file paths from configuration and validates edit references against a fresh per-send snapshot. Reads are bounded to the past 30 days and next seven local dates; edits schedule from a target inside the next seven dates.

Carry-over preserves existing AI task identity, total effort and deadline, subtracts completed history, and retains completed rows and habitual occurrences. Plain handwritten tasks are imported once; explicit time ranges retain duration, missing durations use the configured default. Tasks/Dataview dates and priority fields preserve constraints. Existing AI duration edits, linked/source-managed/nested/locked/completed/habit edits are rejected. Source rows and future output are staged and verified together; backup is saved before compare-and-write. Partial writes retain recovery, and restart undo restores source/destination notes and task state. The host reports actual slots, defaults and unscheduled effort and opens the first destination. Unsatisfied deadlines reject the request.
