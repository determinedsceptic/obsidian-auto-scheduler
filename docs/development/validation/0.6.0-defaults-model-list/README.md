# Defaults and model-list follow-up validation

Author: Alex Hu / Codex. Date: 2026-10-02. Source: the commit containing this record (parent 4a05ad7). Upstream: user-reported missing defaults, invalid glyphs and manual model selection. Downstream: tools, mixed-plan transaction, provider modal, sidebar and plugin assets. Status: local validation passed.

The previous default covered only start-only fixed events and recurring habits. Flexible tasks now accept null duration/minimum block size and resolve them in the host with the configured duration. Missing event dates resolve to the next local occurrence of the specified time. Actual saved times and default assumptions are reported. A create_plan tool combines flexible tasks, exact appointments and habits in a single validated operation and shared undo. Distinct individual tool calls also share that operation; duplicate/unknown calls remain rejected. Invalid control, surrogate, private-use, unassigned and replacement code points are removed from provider prose, while Chinese and standard emoji remain readable.

Provider configuration is now list-first. Refresh model list puts provider discovery results directly into the dropdown; saving retains up to 100 choices including the selected model. Custom IDs are an optional collapsed advanced fallback. Existing providers at known preset endpoints gain preset alternatives without changing their selected model or token. Discovery and actual model capability remain provider-dependent.

Validation: typecheck; 242 tests in 15 files; actual bundle smoke; release checks; packaging. Regressions cover four protocols, flexible defaults, unspecified dates, glyph filtering, preset compatibility, discovered dropdown selection/persistence and mixed gym + phone-number + habit scheduling/undo after restart. Hosted inference was not exercised; tests use injected responses and an isolated host.

Deployment: previous installed assets backed up; three assets copied to the existing undo vault and independent demo vault and hash-verified. The installed plugin was disabled/re-enabled through native Obsidian settings. Native checks confirmed Default duration = 30, the collapsed custom-ID fallback, and both gpt-6-luna and gpt-6-sol in settings and sidebar dropdowns. The sidebar was reopened and the choice list left visible. No real token was read, replaced or transmitted; no private note was edited or published. No real model-discovery or inference request was sent. Existing screenshots remain historical evidence rather than current UI captures.

Review limits: prompt instructions reduce unnecessary clarification, but provider compliance cannot be guaranteed without a real inference. Host defaults are deterministic for null tool fields, and tool validation still rejects invalid times/dates. Ordinary tasks receive the next available working slot; exact appointments retain their start. Multi-file writes use existing backup/recovery checks rather than a claimed atomic filesystem transaction. Undo restores mixed-operation files, tracking and AI tasks together.
